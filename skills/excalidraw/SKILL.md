# Excalidraw Architecture & Diagram Skill (TDS Style + Mirror/Inbox)

This skill guides AI agents in rendering high-quality, non-overlapping, aesthetic system architecture diagrams in pure `.excalidraw` JSON format **from wiki/architecture/*.md SSOT**. Canvas is a mirror/view plus input inbox — never a second SSOT. HTML is a derived auto-view regenerated by scripts/sync-architecture.js (md to html one-way).

## SSOT (single source of truth — read first)

1. **md is master (Ledger)**: `wiki/architecture/*.md` is the only architecture SSOT. Every claim needs `> Raw:` into `raw/`, `index.md` parity, `Vault-Base` hash reachability (check_vault).
2. **Canvas is mirror plus inbox (View + Inbox)**: `architecture.excalidraw` is a human-friendly mirror of md plus a sticky-note inbox. md to canvas is one-way render. Canvas to md/code is allowed only via Echo-confirmed Task (`gate:echo-confirmed`) — never auto-executed.
3. **HTML is derived auto-view**: `architecture.html` is regenerated from md core (tiers plus Changelog) by `npm run sync:architecture`. Never hand-edit html to fix drift — fix md, rerun the script.
4. **Changelog truth is package.json plus log.md**: canvas Changelog card is a mirror copy only. Truth lives in `package.json` version plus `log.md` append-only ledger.

## Core Rules & Guardrails (Toss Design System Style)

1. **Pure JSON Output**: `.excalidraw` files must be valid, well-formed JSON conforming to the Excalidraw Schema v2.
2. **Toss Style Clean Vector Geometry (Zero Roughness)**:
   - **`roughness: 0`**: 삐뚤빼뚤한 손그림 느낌을 완전히 배제하고, 토스/애플 스타일의 반듯하고 정갈한 직선 벡터 사용.
   - **`roundness: { "type": 3 }`**: 부드러운 라운드 카드 모서리 적용.
3. **가독성 극대화 산세리프 타이포그래피 (fontFamily: 2)**:
   - **`fontFamily: 2`** (Helvetica / Clean Sans-serif / Pretendard 계열) 필수 적용. (Virgil/손글씨 폰트 금지)
   - 제목: `fontSize: 14~18`, `strokeColor: "#191f28"` (다크 테마: `#58a6ff` / `#e6edf3`)
   - 본문/설명: `fontSize: 13~14`, `strokeColor: "#4e5968"` (다크 테마: `#8b949e` / `#c9d1d9`)
   - 카드 내부 텍스트는 좌측 정렬(`textAlign: "left"`)과 불릿(`•`) 포맷을 적용하여 가독성을 극대화.
4. **텍스트 짤림 방지 박스 크기 및 여백 규칙**:
   - 텍스트 길이에 맞춰 박스 높이를 넉넉하게 산정 (최소 `height: 75~100px`, 3줄 이상은 `120~160px`).
   - 가로 여백은 좌우 각 10px 이상의 패딩을 확보하여 글자가 박스 밖으로 튀어나가지 않도록 통제.
5. **토스 시그니처 컬러 팔레트 (TDS Palette)**:
   - **카드 바탕**: 순백색 `#ffffff` (다크: `#161b22`)
   - **카드 테두리**: 은은한 그레이 `#e5e8eb` (다크: `#30363d`)
   - **시그니처 블루 (1계층/오케스트레이션)**: 테두리/화살표 `#3182f6` (`#388bfd`), 하이라이트 배경 `#f2f8ff`
   - **인터프리터 퍼플 (2계층/스키마)**: 테두리 `#7c3aed` (`#a371f7`), 하이라이트 배경 `#f5f3ff`
   - **안심 에메랄드 (3계층/게이트&볼트)**: 테두리 `#059669` (`#3fb950`), 하이라이트 배경 `#ecfdf5`
   - **사용자 작업 지시 (Sticky Note)**: 테두리/텍스트 `#e8590c` (토스 오렌지), 배경 `#fff4e6` (`#2d1b0d`)
   - **작업 완료 피드백 (Done Sticky)**: 테두리/텍스트 `#2b8a3e` (그린), 배경 `#ebfbee` (`#102816`)
   - **체인지로그 앰버 (Changelog Card)**: 테두리 `#d97706` (`#d29922`), 하이라이트 배경 `#fffbeb`
6. **Arrow & Binding Rules**:
   - 화살표는 `roughness: 0`, `roundness: { "type": 2 }`.
   - 반드시 `startBinding`과 `endBinding`을 연결하여 노드 이동 시에도 선이 유지되도록 바인딩.

## 스티키 접수함 해석 (Inbox as Diary — Echo gate required)

사용자는 해당 컴포넌트 카드 바로 옆에 스티키 노트를 붙이고 화살표를 꽂아 **다이어리 입력**을 남길 수 있다. AI 에이전트는 이를 즉시 실행하지 않고 diary로 취급한다:

1. **타겟 컴포넌트 식별 (Arrow Binding & Spatial Proximity, read-only)**:
   - 화살표(`type: "arrow"`)의 `endBinding.elementId`가 가리키는 카드를 1순위 후보로 읽는다.
   - 바인딩이 없는 경우, 화살표 끝점 `(x, y)`과 유클리드 거리가 가장 가까운 카드(반경 80px 이내)를 후보로 읽는다. 판정은 인용용이지 실행 근거가 아니다.
2. **지시사항 독해 (Sticky Note Extraction as diary)**:
   - 화살표 시작점 텍스트 또는 사각형 내부 텍스트(예: *"여기를 이렇게 고쳐줘"*)를 diary 원문으로 캡처한다. 추측 금지.
3. **Echo 확정 후 실행 (Echo-first, guardian yes required)**:
   - 스티키는 diary 취급이므로 `guardian` 모드에서는 Echo 요약 plus 사용자 `yes` 승인 없이 실행 불가.
   - 승인 후에는 Lock 스키마(`echo:{summary, confirmed:true}`) plus `gate:echo-confirmed` Task로만 위임한다 (plugins/force-delegation.js fail-closed).
   - 완료 후 스티키를 초록색 `[완료]`로 바꾸는 것은 선택적 시각 피드백이며, 코드 진실이 아니다. 진실은 md plus 코드 diff plus `npm run verify` PASS다.

## Workflow for Code Scanning & Diagram Generation

1. **Discover & Inspect Codebase**:
   - routes, controllers, DB models, config files, `opencode.json` 스캔.
   - 의존성 매핑: Conductor → Interpreter → Verify → Vault.
2. **Design Grid Topology**:
   - 3계층 흐름: `Tier 1: Orchestration` → `Tier 2: Interpretation` → `Tier 3: Gates & Vault`.
3. **Assemble JSON**:
   - `elements` 배열에 노드, 라벨, 화살표, 체인지로그 카드 조립.
   - `"appState": { "viewBackgroundColor": "#0d1117", "gridSize": 20 }`.
4. **Render File From MD (one-way)**:
   - `wiki/architecture/*.md`를 읽어 `architecture.html`을 `npm run sync:architecture`로 재생성한다. `architecture.excalidraw`는 md 기준 거울로만 갱신하며, 캔버스 주석을 코드 진실로 역수입하지 않는다.

## Architecture Sync & Changelog Rules (SSOT enforcement)

1. **md 우선 단방향 렌더 원칙 (No reverse import)**:
   - 신규 파일, 모듈, 스크립트, 플러그인이 추가되거나 변경되면, md SSOT(`wiki/architecture/*.md`)를 먼저 갱신한 뒤 `npm run sync:architecture`로 html 거울을 재생성한다. 캔버스 주석을 md로 역수입하는 것은 Echo 확정 Task로만 허용된다.
2. **변경 이력 카드 (Changelog Card)는 거울 복사**:
   - 캔버스 우측 상단 `📜 아키텍처 변경 이력` 카드는 `package.json` 버전 plus `log.md` 진실을 그대로 옮긴 복사본이다. 진실을 캔버스에서 고치지 않는다. 최신 버전 번호, 수정 일자(YYYY-MM-DD), 핵심 변경 사유(1~2줄)는 log.md append 뒤 스크립트로 동기화한다.
3. **100% 자연스러운 한국어 표기**:
   - 한국어 워크스페이스에서는 직관적인 한국어(예: 3계층 구조, 1트랙~4트랙 파이프라인 등)를 사용하여 한눈에 시스템을 장악할 수 있도록 한다.
4. **Echo 매핑 (Zero-CLI 자동완결 금지)**:
   - `Zero-CLI 자율 완결`, `한 트랜잭션으로 코드 수정과 다이어그램 갱신을 자동 완결`, `양방향 실시간 동기화` 문구는 금지된다. 스티키는 diary이며, 실행은 항상 Echo 요약 plus 사용자 확인 plus Lock 스키마 plus `gate:echo-confirmed` 위임 plus `npm run verify`를 거친다. 터미널 명령 회피가 목표가 아니라 SSOT 정합이 목표다.
